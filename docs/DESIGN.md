# Design notes

This file records why refdiff is built the way it is, and what went wrong along the way. The README shows
where the project ended up; this shows how it got there. Numbers in the README are regenerated by
scripts. Numbers here are **historical**: each one comes from a logged run at the time it describes, and
is kept as it was so that the decision it drove still makes sense.

## Decisions

**Classify the regions that changed, rather than detecting over the whole image.** With a reference, the
question "where could a defect be?" has a cheap, almost exact answer: wherever the test differs from the
template. That leaves the learned part a small, well-posed job: name what changed, or call it noise. It
also explains the failure modes. A defect the diff cannot see cannot be found, and the error analysis
counts those cases separately (*diff empty*, *diff box off*).

**A tolerant, signed XOR rather than an absolute difference.** DeepPCB images are binary, so a grey-level
difference adds nothing. What matters is which way copper changed: extra copper (short, spur, spurious
copper) or missing copper (open, mousebite, pin hole). The tolerance (a pixel counts only if the other
image has no copper within `tol` px) absorbs sub-pixel residue and etch-edge jitter. Polarity was checked
on the data, not assumed: a short has to come out as *extra*. Box padding and tolerance were fitted on
trainval by candidate recall, never on test.

**Score registration on synthetic warps.** The as-shipped DeepPCB pairs were aligned by integer template
matching, so their true residual warp is unknown, and there is nothing to score against. The synthetic
test pastes each pair's real defect patches onto its template and applies a known warp (and optics), so
the error can be measured exactly. The as-shipped pairs are still used, but only for what can be
measured on them: how far registration moves them, and how much off-defect mismatch it removes.

**A guard over several registration methods rather than one method.**
- Fourier–Mellin can lock one pitch off on periodic pad arrays.
- ECC from identity cannot reach large shifts.
- Phase correlation alone cannot see rotation.

Each fails on different images, so the guard runs all of them and keeps the one whose warped test best
matches the template. When even the best match is poor, it flags the pair for review instead of
returning a confident wrong answer.

**Write our own scorer.** The official DeepPCB script is Python 2 and needs the `Polygon` package.
`refdiff/metrics.py` re-implements its matching rule (IoU > 0.33 with a same-class box, VOC all-point AP),
so CI can run it. As a result, our numbers are close to the paper's, not identical.

**Export the classifier to ONNX and commit it.** The CI gate and the demo then need only OpenCV and
onnxruntime, not torch. The model is 2.4 MB, and its outputs match the torch checkpoint to 3e-7.

**Keep ultralytics out of the package.** It is AGPL-3.0. The YOLO baselines install it as an optional
extra, and nothing in `refdiff/` imports it.

## Dead ends and bugs, in order

1. **Crop padding overflow.** Large candidate boxes ran past the fixed padding around the image, and the
   crops came out wrong. The padding is now sized from the largest box in each image.

2. **A 10-minute eval that should take seconds.** Indexing `np.load(...)["crops"]` inside the per-image
   loop decompressed the whole crop array on every access. The arrays are now loaded once.

3. **The first CI gate run failed, and was right to.** Under different random warps from the
   development runs, it reported:

   | | measured | limit |
   |---|---|---|
   | p95 | 0.97 px | 0.75 px |
   | max | 21.9 px | 5 px |

   Tracing the 21.9 px case showed the guard was unfair. It compared NCC over each candidate's own
   coverage, so identity, which covers the whole frame, was scored on a different (larger) area than a
   real warp. Three changes fixed it:
   - All candidates are now scored on the region they *all* cover.
   - Warps that leave less than half the frame covered are dropped first.
   - A confidence flag (NCC < 0.5) marks pairs the guard cannot vouch for.

   The gate now checks the worst *confident* error and the fraction flagged, rather than a raw max.

4. **Gate limits too tight for CI.** After the fix, the median sat at 0.1495 px against a 0.15 px
   ceiling. A CI runner with different floating-point behaviour would fail at random. The limits were
   loosened to margins that still catch a real regression. The ones in `eval/gate.json` are an explicit
   choice, recorded here, not tuned to pass.

5. **Die-to-database recall of 75%.** Registration on the synthetic layouts was excellent from the start.
   Defect recall was not. Broken down by defect type, the cause was the injected-defect *labels*, not
   the detector: a label box covered the whole painted shape, including pixels the defect did not
   change. Labels now cover only changed pixels. The same edit had an aliasing bug: `out = prev` let the
   next paint modify the saved copy, so it is now `prev.copy()`. The diff parameters were tuned on one
   set of layout seeds, and the reported numbers use seeds from 1000 up, which were never tuned on.

6. **The error taxonomy mislabelled fragments** (failure analysis). Its first version filed detections
   of *part* of a labelled crack under "no defect". Looking at the gallery showed the crack was labelled,
   as one large box, so the cause is now *fragment*: at least half the detection lies inside a labelled
   defect. The lesson: automatic error tags need checking against the images.

7. **A hypothesis that failed** (failure analysis). Four DeepPCB test boards never appear in trainval. I
   expected the template-blind YOLO to suffer most on them. It does not: both methods score higher on the
   unseen boards. YOLO's false alarms cluster instead on board *style*, especially white gaps cut into
   solid copper, where a template-free model cannot tell an intended gap from an open.

8. **Faster registration, two wrong turns** (speed pass). Profiling put 61% of the time in ECC: three
   chains, each building the same pyramid and each running the expensive full-resolution level. Sharing
   the pyramid, and one full-resolution pass per distinct warp, cut end-to-end time by about 30% with
   identical accuracy. Two things went wrong on the way:
   - **Fourier estimates at half resolution.** Tried and reverted: 29% of ±3°/±20 px warps landed more
     than 2 px off, against 6% at full resolution, because the log-polar spectrum is too coarse to pin
     the rotation.
   - **A double rescale of the translation** in the split ECC loop. The registration eval caught it
     (p95 jumped from 0.3 px to 25 px) while the unit tests still passed. The guarded path now has a
     rotation-and-shift test that fails on that bug.

9. **What the CNN adds** (baselines). The same candidates classified from geometry alone (sign, size,
   aspect, fill), using gradient-boosted trees, reach about a quarter of refdiff's mAP. The confusion
   matrix shows why:
   - The sign separates the two families perfectly.
   - Geometry separates defects from background well.
   - Within a family (open vs mousebite vs pin hole), geometry is close to chance.

   The diff says *where* and *which family*. The pixels say *what*.

10. **The template-aware YOLO, first attempt** (baselines). Ultralytics' default colour augmentation
    shifts hue and saturation. On a composite image whose channels *mean* test, template and diff, that
    scrambles the input. The run was stopped at epoch 1, and HSV augmentation is off for that input.

11. **The second dataset: three wrong starts** (PKU transfer).
    - **The debug subset was one class.** "First 40 samples" sorted to 40 missing-hole images, the
      one class with no DeepPCB counterpart. Debug subsets are now spread across boards and classes.
    - **Scaling by trace width.** The first plan scaled each PKU board so its traces were as wide as
      DeepPCB's. Measured, DeepPCB's own boards range from 8 to 78 px of copper width, so there is no
      single target. And PKU's defects are large relative to its traces, so matching widths made
      defects about twice DeepPCB size. The pipeline's pixel parameters were fitted to *defect* size,
      so the scale is now one global ratio of median defect-box sizes, with a sweep reported beside it.
    - **Fourier–Mellin on the real rotated set.** On synthetic warps of PKU images, registration is
      near-perfect. On PKU's own rotated copies (about 9°, on a larger canvas), Fourier–Mellin alone
      returns about 0°. The guard recovers the rotation through ECC, and SIFT agrees. Unlike DeepPCB,
      PKU boards are not periodic pad arrays, so keypoints work there.

    - **"Pixel-aligned" was only nearly true.** Registration lifted the as-shipped PKU images' mAP even
      though I had called them pixel-aligned. Checked board by board: most are exact, but all of board
      10 is 0.5 px off and some board-01 images 1 px. On a binary XOR, one pixel of offset leaves a
      sliver along every edge.

## Open questions

- On PKU, a few registrations under known warps land far off (the README's PKU table gives the count),
  and the guard flags none of them. Its confidence threshold was set on DeepPCB, and on these images
  overlap NCC evidently stays high even when the warp is wrong. Not yet investigated: the first step is to
  look at those pairs.
- Most of refdiff's false alarms are one defect split into two diff blobs, or found in part. Better blob
  grouping (merging same-sign blobs across a gap, or a containment-aware NMS) should remove most of them.
  It has not been tried yet.
- Boards of long parallel traces leave registration residue along the traces (the aperture problem), and
  shorts on those boards merge into it. A registration prior that penalises motion along the dominant
  trace direction might help.
